The Governance agent runs at the end of every pipeline run to assemble the complete record of what happened. It collects structured outputs from every upstream stage, constructs the run log, writes the corpus change record, publishes health metrics to your pipeline dashboard, and flags any anomalies for your attention.

Governance is what makes the pipeline trustworthy at scale. Every routing decision, confidence score, approval action, and quality finding is captured and searchable — traceable from a published documentation change all the way back to the product change event that triggered it.

## The run log

At the end of every run, the Governance agent assembles a complete structured run log from the outputs of all upstream stages.

```json
{
  "run_id": "...",
  "timestamp": "...",
  "change_event_id": "...",
  "routing_manifest": { "..." },
  "agents_dispatched": ["01", "02", "03", "04", "05"],
  "impact_summary": {
    "pages_affected": 4,
    "severity_breakdown": { "critical": 1, "high": 2, "medium": 1 }
  },
  "approval_event": {
    "approver": "...",
    "timestamp": "...",
    "components_approved": 3,
    "components_edited": 1,
    "components_rejected": 0
  },
  "quality_summary": {
    "findings_critical": 0,
    "findings_warning": 2,
    "findings_info": 1
  },
  "token_consumption": 34800,
  "pipeline_duration_seconds": 47,
  "anomalies": []
}
```

Every field is populated from structured outputs produced upstream. The Governance agent assembles — it does not infer, estimate, or fill gaps.

## Anomaly detection

The Governance agent evaluates each run against a set of threshold-based anomaly checks. Flagged runs appear in your pipeline health dashboard for investigation. They do not block publication — your approval already cleared them — but they are a signal that something in the run deserves a closer look.

| Signal | Anomaly threshold | Action |
|--------|------------------|--------|
| Token consumption | Greater than 150% of baseline | Flagged for review |
| Pipeline duration | Greater than 200% of baseline | Flagged for review |
| Confidence scores | Any stage below minimum threshold | Flagged for review |
| Approval edit rate | More than 50% of components edited | Flagged for review |
| Quality findings | Any critical severity finding | Flagged for review |
| Escalation events | Any escalation triggered during the run | Flagged for review |

When a run produces multiple anomaly signals, the Governance agent adds a short plain-language summary describing what the pattern typically indicates and what to check first.

## The corpus change record

For every approved and published update, the Governance agent writes a corpus change record containing:

- The page identifier
- The change type (update / addition / removal)
- The change event that triggered the update
- The approver identity and timestamp
- Content hashes for the pre-update and post-update versions of the page

The corpus change record is append-only. Records cannot be modified or removed after they are written. This means you always have a complete, trustworthy history of every change made to your knowledge base through the pipeline — traceable back to the product change event that initiated it. This is an architectural guarantee, not a setting.

## Pipeline health metrics

Across runs, the Governance agent accumulates metrics that show you how the pipeline is performing over time:

- **Per-agent confidence trends** — whether any agent's output quality is degrading
- **Approval edit rate** — which agent's outputs are being edited most frequently, and by how much
- **Rejection rate by component** — which output types are being rejected
- **Rule firing frequency** — which quality rules are triggered most often
- **Token consumption trends** — whether per-run cost is increasing

These metrics are the primary signal for when prompt tuning, rule corpus updates, or detector adjustments are needed.

<Tip>
A high edit rate on a specific agent's output is a signal that its prompt may need tuning — the governance metrics show you exactly where manual correction is most frequent. If writers are consistently making the same edit to the Communications agent's drafts, that pattern should be reflected in the prompt, not remain as recurring manual work at the approval gate.
</Tip>
